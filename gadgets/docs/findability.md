# Being found and shared

Traffic is the binding constraint on this business: 122 devices and 54% affiliate coverage earn nothing without visitors. This is what the site now does about that technically. It is not a marketing plan — that is a separate problem.

## What the build emits

| Thing | Where | Why |
|---|---|---|
| `sitemap.xml` | generated at build, 149 URLs | Search engines cannot rank pages they never find. Device pages get priority 0.8, guides and comparisons 0.7, the home page 1.0. The order confirmation page is excluded. |
| `robots.txt` | generated at build | **Blocks everything by default**, because the preview must not be indexed before sources, image permissions and the domain are settled. Set `GADGETS_PUBLIC=1` at build time to allow crawling and advertise the sitemap. |
| `<link rel="canonical">` | every page | The catalog has filter URLs (`/hardware/?category=radio&sort=name`). Without a canonical, those look like hundreds of duplicate pages. |
| `og:image` | every page | A link pasted into Reddit, Discord, Slack or X renders with a picture. Device pages use the device photo; everything else uses `/assets/og-default.png`. This matters more than it sounds: sharing is the growth channel in this niche, and a preview-less link gets far fewer clicks. |
| `og:url`, `og:site_name`, `twitter:card` | every page | Large image cards instead of a bare link. |
| schema.org `Product` JSON-LD | device pages | Name, description, image, brand, and a link to the maker. When a device has an active Buy listing it also carries price and stock, which is what earns a rich result in search. |

Set the domain with `GADGETS_SITE_ORIGIN` (defaults to `https://gadgets.sh`). Canonicals and the sitemap follow it.

## At launch

```bash
GADGETS_PUBLIC=1 GADGETS_SITE_ORIGIN=https://gadgets.sh npm run build
```

Then submit the sitemap in Google Search Console and Bing Webmaster Tools. Until then every build keeps the site out of search on purpose.

## What is still missing

- **No per-page title tuning.** Titles are `{device} — gadgets.sh`. Real queries look like "flipper zero alternatives" or "best meshtastic node", which are comparison-shaped, not product-shaped. The comparison and guide pages are the ones that could rank for those; they need titles written for the query, not for the product.
- **No `BreadcrumbList` or `ItemList`** structured data on category and comparison pages.
- **No image alt-text audit.** Device photos have alt text; decorative images should be checked.
- **`og-default.png` is generated by hand** (`public/assets/og-default.png`, 1200×630). Replace it if the brand changes.
